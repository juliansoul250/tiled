# 从 Tiled 直接导入到 Unity 2022.3

这不是外链教程或让你手动复制文件的菜单：Tiled 会检查当前地图及依赖，预览文件清单，确认后将它们安全送入所选 Unity 项目，并按需安装随应用内置的官方 SuperTiled2Unity 2.4.0。

## 操作步骤

1. 先备份 Unity 项目，关闭该项目的 Unity 编辑器。保持 Unity 关闭，直到传送完成，避免两个程序同时改动资源。
2. 在 Tiled 打开地图，将地图保存为 **TMX（XML）**；外部瓦片集使用 **TSX**，模板使用 **TX**。图层数据推荐 CSV，也支持导入器支持的 Base64/zlib/gzip；不要选 Zstandard/zstd。
3. 保存所有已打开且修改过的地图、瓦片集和模板。当前实现会拒绝带未保存更改的状态，绝不会偷偷导入旧磁盘内容。
4. 点击 **文件 → 导入到 Unity…**，选择包含 `Assets`、`Packages`、`ProjectSettings` 的 Unity **2022.3** 项目根目录，不要只选择 Assets。
5. 阅读确认框，展开详细信息检查新增、更新、移除的旧依赖清单。不确定时点击取消：预览和取消不会写入项目。
6. 完成后会显示目标 TMX 路径。重新用 Unity 2022.3 打开该项目，等待 Unity 的 Package Manager、脚本编译和资源导入完成。随后在 Project 窗口查找 `Assets/TiledImports` 下的地图资源，由 SuperTiled2Unity 导入。

**“文件已送入”不等于 Unity 已生成预制体成功。** 如 Unity 报错，查看 Console 控制台；不要继续反复覆盖项目。当前开发/CI 环境没有已授权的 Unity 2022.3 编辑器，不能据文件传送测试声称已实测 Unity 场景或预制体。

## 文件与更新规则

- 每张源地图使用独立、稳定的受控子目录，目录名称由源地图绝对路径计算。地图移动位置后会作为新的导入来源，原导入目录不会被擅自删除。
- 递归收集 TMX、外部 TSX、TX 模板与支持的图片/被动依赖，重写副本里的相对路径；**不会修改源地图**。依赖的源路径可包含中文和空格，同名资源按来源分开保存。
- 再次导入只允许更新本工具此前管理且未经手动修改的文件。相应 Unity `.meta` 会保留以维持 GUID；未知文件、手动修改、缺失记录或符号链接会导致拒绝覆盖。旧依赖删除会在预览中列出。
- `Packages/manifest.json` 和 `packages-lock.json` 不会被重写。首次安装仅创建 `Packages/com.seanba.super-tiled2unity`；已有完全一致的内置包可复用。不同版本、修改过的包、清单中的已有安装声明或识别出的旧 Assets 插件安装均需先人工处理，不会静默升级或删除。
- 写入先暂存，再提交；遇到普通文件操作失败会恢复原有内容。若恢复也失败，将保留并显示恢复目录，请保留现场联系维护者。不要将此当作断电、磁盘损坏或其他程序恶意并发写入情况下的完整文件系统事务保证。

## 支持范围与常见提示

- 当前入口限定 XML TMX/TSX/TX；JSON 的 TMJ/TSJ、外部 JSON 瓦片集、内嵌图片、DTD、自定义 XML 实体、网络地址依赖和符号链接不支持。请先另存为支持的格式，而不是直接改扩展名。
- 依赖使用本地相对路径；绝对路径和含反斜杠的引用需先在 Tiled 中整理。`../` 依赖会检查真实文件并重写到受控目录，不会按原路径写出 Unity 项目。
- 支持正交、等距、交错、六边形地图；不支持斜投影 oblique。无限地图的区块由导入器处理，不能因此声称具有游戏运行时流式加载功能。
- 自定义类属性、特殊渲染效果及所有 Tiled 新特性不能保证与 Unity 等价。隐藏图层、Pixels Per Unit、渲染管线、碰撞设置等仍取决于 SuperTiled2Unity 和 Unity 项目配置。
- 对象中的文件属性仅允许受限的被动依赖，不会借文件引用复制 C#、DLL 或其他可执行代码进 Assets。超大或缺失依赖会明确报错。
- 插件本体已随本应用离线提供，**Unity 解析依赖包时仍可能联网**，首次打开并不保证离线成功。不会要求你在 Mac 安装 Python、git 或 Homebrew 来使用菜单。

## 自动验证的边界

CI 除文件转移单元测试外，还在独立 Cocoa 测试进程中创建真实 Tiled 主窗口，从应用包内启动测试入口，点击同一个“导入到 Unity”菜单，检查取消选择、取消确认、确认传送及重复更新，并使用应用包内真实的固定导入器文件。对话框仅在测试进程采用可自动操作的 Qt 文件选择器；正常应用仍使用系统默认对话框。此验证不启动 Unity Editor，也不能替代 Unity 侧的编译、预制体和场景验收。
